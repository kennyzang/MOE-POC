## Work Completed

### Bug: Consent forms empty on mobile
- **Root cause:** `ParentConsentFormsPage.tsx` called `/parent/consent-forms` — a non-existent route. Backend only registers `/communications/consent-forms`.
- **Fix:** Updated GET and acknowledge POST endpoints to `/communications/consent-forms/*`

### Bug: Teacher can see notification but can't reply
- **Root cause:** `NotificationBell.tsx` `handleItemClick` only marked notification as read but never navigated to `item.link`.
- **Fix:** Added `useNavigate` + close popup + navigate to `item.link` when notification has a link. Teacher now goes directly to `/teacher/messages` on tap.

### Bug: Parent can't initiate messages from mobile
- **Root cause:** `ParentMessagesPage.tsx` (mobile) had no "New Message" button — only showed existing threads. PC has a full compose modal.
- **Fix:** Added `ComposePopup` bottom sheet with teacher selector (from `/parent/meetings/teachers`), subject field, and message textarea. Floating `+` FAB opens the sheet. Added i18n keys to all 3 locales (en/zh/ms).

### Bug: Message detail title shows wrong fallback
- **Root cause:** `GET /messages/threads/:id` returned raw thread without `parentName`/`teacherName` enrichment, so mobile detail title fell back to generic text.
- **Fix:** Backend now looks up participant names and includes them in the detail response.
