## 问题与修复

### 问题 1（HIGH）：Sidebar 角色专属 Portal 与主 Section 重叠

**根本原因**：counselor / hod / finance 同时存在于主 Section 的 roles 数组，
AND 各自的 Portal 里也有相同链接，导致同一用户在侧边栏看到同一页面两次。

**影响范围**（修复前 15 处重复）：
- Counselor Portal：/sis/students / /sis/behavior / /sen/students 与 SIS Section 重叠
- HOD Portal：/ems/teachers / /ems/performance-evaluations / /ems/leave / /ems/cpd-workshops 与 EMS Section 重叠
- Finance Portal：/sms/finance / /sms/library 与 SMS Section 重叠

**修复**：
1. SIS Group roles 移除 'counselor' → counselor 只通过 Counselor Portal 访问 SIS 内容
2. EMS Group roles 移除 'hod' → HOD 只通过 HOD Portal 访问 EMS 内容
   - HOD Portal 补充 /ems/certifications、/ems/workload（两个 EMS 新增链接，之前 HOD Portal 缺失）
   - HOD Portal 补充 /sms/exams（考试管理也与 HOD 相关）
3. SMS Group roles 移除 'finance' 和 'hod' → 各自通过 Portal 访问

验证方法：编写 node 脚本，对每个 UserRole 枚举其能看到的路由，确认无同一角色重复。

### 问题 2（MEDIUM）：`StudentOption` interface 定义重复 3 次

`ExamsPage.tsx:48`、`SenStudentsPage.tsx:66`、`LibraryPage.tsx:68` 各自定义了
完全相同形状的 interface，且无法从 types/index.ts 看出是否有规范定义。

**修复**：
- 在 `pc/src/types/index.ts` 添加 `StudentSearchResult` 导出（与 comment 说明其用途）
- 三处 inline interface 改为 `type StudentOption = StudentSearchResult`

### 问题 3（MEDIUM）：学生搜索 React Query 块重复 4 次

`queryKey: ['students-search', term]` + `GET /students?search=...` 的完全相同逻辑
在 ExamsPage（1次）、SenStudentsPage（1次）、LibraryPage（2次，分别对应借书/预约弹窗）
共出现 4 次。

**修复**：
- 新建 `pc/src/hooks/useStudentSearch.ts`
- 导出 `useStudentSearch(term: string)` hook，内含 enabled guard（≥2 字符）和 placeholderData: []
- 四处 useQuery 块替换为 `useStudentSearch(searchTerm)`
- React Query 会对相同 queryKey 的结果进行缓存共享（如两个弹窗同时搜索相同词时只发一次请求）

### 问题 4（LOW）：`searchTimer` 反模式

`LibraryPage.tsx` 和 `InventoryPage.tsx` 在函数体内定义 `const searchTimer = { current: 0 }`，
每次重渲染都创建新对象，`clearTimeout` 对旧对象 id 无效（竞态）。

**修复**：改用 `useRef<ReturnType<typeof setTimeout>>()` —— 引用在组件整个生命周期内稳定。
