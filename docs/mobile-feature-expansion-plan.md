## 四、实施优先级建议（距演示 4 天）

### 方案 A：最小有效演示（1-2天工作量）
> 后端零改动，演示亮点显著提升

| 优先级 | 功能 | 原因 |
|--------|------|------|
| 1️⃣ | **AI 聊天助手** | 复用 PC 端 SSE 接口，移动端增加浮动按钮 + 聊天界面，演示亮点最高 |
| 2️⃣ | **公告列表页** | 首页卡片已有，缺落地列表页，1-2h 即可完成 |
| 3️⃣ | **应用内通知列表** | 与已有 Web Push 形成闭环，家长体验完整 |

### 方案 B：完整 P1（2-3天工作量）
在方案A基础上增加:

| 优先级 | 功能 | 说明 |
|--------|------|------|
| 4️⃣ | **家长消息中心** | 演示"Ahmad家庭"叙事链路最后一环 |
| 5️⃣ | **教师签到（移动端）** | 演示教师到校手机打卡，PC 端也有对应页面 |

### 方案 C：演示后迭代（不建议在演示前做）
P2/P3 所有功能，结构更复杂，风险更大，演示后稳步实现。

## 五、技术实现关键点

### AI 聊天助手
```
PC 端已有:  pc/src/components/ChatWidget/ (SSE 流式响应, 按角色预设问题)
移动端方案: 浮动按钮(FAB) + 全屏 Drawer + useChatStream Hook
接口复用:   POST /api/v1/ai/chat (SSE, 已支持所有角色)
UI 组件:    antd-mobile Popup / FloatingBubble
```

### 应用内通知列表
```
PC 端已有:  pc/src/components/NotificationBell/ + notificationStore
移动端方案: 首页顶栏铃铛图标 + 通知 Drawer (或独立页)
接口复用:   GET /api/v1/notifications, PATCH /api/v1/notifications/:id/read
```

### 公告列表
```
PC 端已有:  pc/src/pages/SIS/Announcements/
移动端方案: 首页"公告"卡片点击跳转列表页 /student/announcements
接口复用:   GET /api/v1/announcements (已分角色过滤)
AnnouncementDetailPage 已有: 直接复用
```

### 家长消息中心
```
PC 端已有:  pc/src/pages/ParentPortal/Messages/
移动端方案: 家长新增 Tab "消息" + 对话列表 + 发送
接口复用:   GET/POST /api/v1/messages
```

## 六、风险提示

| 风险 | 说明 | 缓解措施 |
|------|------|---------|
| 时间紧张 | 距演示仅 4 天 | 优先 P1 中的 AI 助手+通知，其余演示后做 |
| 功能堆砌 | 移动端加功能后演示路线可能混乱 | 新功能纳入演示脚本第 8 段 (Mobile PWA, 5min) |
| TabBar 溢出 | 家长/教师新增 Tab 后底栏超过 5 个 | 将通知/AI 整合进首页顶栏，不新增 Tab |
| i18n 漏网 | 新页面忘记过 i18n | 每个新页面建完后 grep 检查 |
