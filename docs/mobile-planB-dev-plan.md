## ⚠️ 质量问题根因分析 & 解决方案

### 现象
AI 开发的功能通常只完成"骨架"——API 调用了、数据渲染了，但缺乏：
- 加载中的骨架屏（直接 SpinLoading 了事）
- 空状态（没数据时页面空白或报错）
- 下拉刷新（列表不能刷新）
- 错误状态提示（接口失败无反馈）
- 真实交互细节（点击效果、状态流转）
- 移动端专属体验（滑动操作、haptic 感）

### 根本原因
开发前没有"**视觉验收标准**"——用文字描述需求，AI 会取最小实现路径。

### 解决方案：每项功能开发前必须定义以下内容

```
【功能名称】
1. 数据来源: 调哪个 API，返回什么字段
2. 所有状态:
   - 加载中: Skeleton 还是 SpinLoading，骨架几行
   - 成功: 列表展示什么字段，卡片长什么样
   - 空状态: 显示什么图标+文字
   - 错误状态: 显示什么，是否支持重试
3. 交互:
   - 下拉刷新: 是否支持
   - 点击后: 跳转哪里 / 展开什么
   - 操作按钮: 有哪些，点击后的状态变化
4. 边缘情况:
   - 内容过长: 截断还是换行
   - 数字超大: 格式化方式
```

**每项功能下面已按此格式完整定义。AI 开发时必须完全遵守这些规格，不得简化。**

## 功能 1：公告列表页（Announcements List）

> 工时估算: 2-3h | 开始条件: 立即 | 后端 API: `/api/v1/announcements` ✅

### 开发背景
移动端首页各角色都有"公告卡片"，点击"查看更多"后**无跳转目标**。  
`AnnouncementDetailPage` 已存在，只缺列表落地页。

### 新增路由
```
/student/announcements
/parent/announcements
/teacher/announcements
```
（统一实现一个组件 `AnnouncementsPage`，通过 query 区分角色）

### 状态规格

| 状态 | 实现要求 |
|------|---------|
| **加载中** | 3 行 Skeleton 卡片，高度 80px，宽度随屏幕 |
| **成功** | 卡片列表，每张卡片含：标题（加粗）、摘要（2行截断）、发布日期（dayjs 格式化 "Jun 5"）、重要性 Tag（URGENT=红/NOTICE=蓝/INFO=灰）|
| **空状态** | Megaphone 图标（48px，灰色）+ "暂无公告" 文字，居中 |
| **错误状态** | ExclamationCircle 图标 + "加载失败，点击重试" + 重试按钮 |

### 交互规格
- **下拉刷新**: 支持 `PullToRefresh`（antd-mobile 组件）
- **点击卡片**: 跳转 `/announcement/detail?id=xxx`（已有详情页）
- **置顶公告**: 带图钉图标（Pin，lucide），排在列表最前面
- **URGENT 公告**: 卡片左侧有 3px 红色竖线

### 集成到首页
- 各角色首页公告区域的"查看更多"按钮，点击跳转到上述路由
- 首页只展示最新 3 条，列表页展示全部（按 `createdAt` 倒序）

## 功能 2：应用内通知列表（In-App Notifications）

> 工时估算: 3-4h | 后端 API: `/api/v1/notifications` ✅

### 开发背景
移动端已有 Web Push（后台推送），但打开 App 后没有通知中心，  
用户无法看历史通知。PC 端有完整的 `NotificationBell` + 通知 Drawer。

### 实现方式
**不新增 Tab**，在各角色 AppLayout 顶栏右上角加铃铛图标（Bell，lucide），  
点击打开底部 `Popup`（antd-mobile Popup，高度 80vh）展示通知列表。

### 状态规格

| 状态 | 实现要求 |
|------|---------|
| **铃铛未读角标** | 红色圆点（不需要数字），有未读通知时显示 |
| **加载中** | 4 行 Skeleton |
| **通知卡片** | 图标（Bell/AlertCircle/CheckCircle，按 type 区分）+ 标题 + 时间（相对时间：dayjs `fromNow()`）+ 正文摘要（1行截断）|
| **未读通知** | 卡片背景 `#EFF6FF`，左侧 3px 蓝色竖线 |
| **已读通知** | 白色背景，正常对比度 |
| **空状态** | Bell 图标（灰色）+ "暂无通知" |

### 交互规格
- **点击通知**: 标记为已读（`PATCH /notifications/:id/read`），如有跳转目标则导航
- **顶部操作**: "全部标为已读"文字按钮（右上角）
- **下拉刷新**: 支持（Popup 内列表支持 `PullToRefresh`）
- **轮询**: 60 秒自动刷新未读数（轮询仅刷新铃铛角标，不刷新列表内容）

### AppLayout 改造
在 `mobile/src/components/AppLayout.tsx` 中，  
顶栏右侧增加 `NotificationBell` 组件（抽成独立组件），所有页面共享。

## 功能 3：AI 聊天助手（Chat Assistant）

> 工时估算: 4-5h | 后端 API: `/api/v1/ai/chat` SSE ✅

### 开发背景
PC 端有 `ChatWidget`（浮动气泡 + SSE 流式回复 + 角色预设问题）。  
移动端无任何 AI 入口。这是演示最大亮点之一。

### 实现方式
全局浮动气泡按钮（FAB），点击打开全屏聊天 Popup。

### 组件结构
```
<ChatFAB />              ← 右下角浮动按钮 (Bot 图标, 48px圆形)
  └── <ChatPopup />      ← Popup 全屏覆盖
        ├── Header       ← "AI 助手" 标题 + 关闭按钮
        ├── MessageList  ← 对话历史（气泡样式）
        │     ├── AssistantMessage  ← 左对齐，蓝色主题，支持 Markdown 渲染
        │     └── UserMessage       ← 右对齐，灰色背景
        ├── PresetQuestions         ← 首次打开时显示 3 个预设问题按钮
        └── InputBar     ← 输入框 + 发送按钮
```

### 状态规格

| 状态 | 实现要求 |
|------|---------|
| **流式输出中** | 消息末尾显示 `DotLoading`（antd-mobile 三点动画），完成后消失 |
| **发送中** | 输入框 + 发送按钮 disabled |
| **空对话** | 机器人头像居中 + "你好，我是 MOE SERPS AI 助手" + 3 个预设问题卡片 |
| **错误** | AI 气泡显示 "抱歉，响应出错，请重试" + AlertCircle 图标 |

### 预设问题（按角色）
```
学生: ["我今天有哪些课？", "我的 GPA 是多少？", "本周作业截止日期？"]
家长: ["我的孩子今天出勤了吗？", "最近有什么学校公告？", "缴费状态如何？"]
教师: ["今日课表是什么？", "哪些学生缺勤？", "待批改的成绩有多少？"]
```

### 技术要点
- SSE 流式响应：使用 `fetch` + `ReadableStream`（不用 axios，axios 不支持流）
- PC 端 `ChatWidget` 的 SSE 逻辑可直接参考：`pc/src/components/ChatWidget/`
- Markdown 渲染：用 `react-markdown`（mobile 已有或 npm add）
- 对话历史存 `useState`，不持久化（关闭即清空）

### 位置规格
- FAB 位置：右下角，距底部 `calc(TabBar高度 + 16px)`，避免遮挡 TabBar
- z-index: 999，所有页面均可见

## 功能 4：家长消息中心（Parent Messages）

> 工时估算: 5-7h | 后端 API: `/api/v1/messages` ✅

### 开发背景
家长需要与教师直接沟通。PC 端有完整的消息线程页面。  
移动端的"缺席原因提交"已证明家长需要主动操作功能。

### 新增路由 & Tab
在家长底部 TabBar 增加第 4 个 Tab：

```
家长 TabBar:
  [首页]  [成绩]  [考勤]  [消息]  ← 新增
```

路由: `/parent/messages`（线程列表）  
路由: `/parent/messages/:threadId`（对话详情）

### 消息线程列表页 规格

| 状态 | 实现要求 |
|------|---------|
| **加载** | 3 行联系人 Skeleton（头像圆形 + 两行文字） |
| **线程卡片** | 头像（教师名首字母，圆形彩色背景）+ 教师姓名（加粗）+ 最后一条消息摘要（1行截断）+ 时间（`fromNow()`）+ 未读红点 |
| **未读线程** | 教师姓名加粗，消息摘要也加粗，右侧红色角标（未读数） |
| **空状态** | MessageSquare 图标 + "暂无消息" + "开始对话"按钮 |
| **下拉刷新** | 支持 |

### 对话详情页 规格

| 元素 | 实现要求 |
|------|---------|
| **消息气泡** | 我的消息：右对齐 + 蓝色背景 + 白色字体；对方：左对齐 + 白色背景 + 边框 |
| **时间戳** | 同一天的消息显示时间（14:30），跨天显示日期 |
| **进入时** | 自动滚动到最新消息，并将未读标记已读（`PATCH /messages/threads/:id/read`）|
| **加载历史** | 消息加载中显示 3 个 Skeleton 气泡 |
| **发送** | 底部输入框 + Send 图标按钮；发送成功后消息即时追加到列表顶部（乐观更新）；发送失败显示 Toast 错误 |
| **发送状态** | 发送中消息气泡右下角显示 `⋯`，成功后消失 |

### API 对应
```
GET  /messages/threads              → 线程列表
GET  /messages/threads/:id          → 线程详情（含消息）
POST /messages/threads/:id/messages → 发送消息
PATCH /messages/threads/:id/read    → 标记已读
```

## 功能 5：教师签到/签退（Teacher Check-In）

> 工时估算: 4-5h | 后端 API: `/api/v1/staff-attendance` ✅

### 开发背景
PC 端有 `StaffCheckInPage`，教师到校手机打卡是**移动端最天然的场景**。  
演示时可展示教师手机端打卡 → PC 端管理员仪表板实时变化。

### 实现方式
教师 TabBar 在"首页"Tab 内增加打卡区域（**不新增 Tab**，整合进首页顶部）。

### 签到区域规格（首页顶部 Card）

```
┌─────────────────────────────────────────┐
│  📍 今日考勤                              │
│                                          │
│  [未打卡]  09:15 AM ← 当前时间实时显示    │
│                                          │
│  ┌──────────┐  ┌──────────┐              │
│  │  ✅ 签到  │  │  🚪 签退  │              │
│  └──────────┘  └──────────┘              │
│                                          │
│  今日状态：已签到 09:02 | 未签退           │
└─────────────────────────────────────────┘
```

### 状态规格

| 状态 | 显示 |
|------|------|
| **未打卡** | 两个按钮均可点击（签到为主色，签退为灰色 disabled）|
| **已签到未签退** | 签到按钮变灰（disabled）+ 显示签到时间；签退按钮为主色可点 |
| **已签到已签退** | 两个按钮均灰，显示"今日已完成签到签退" |
| **周末/假日** | 卡片显示"今日无需打卡"（通过校历判断，或简单判断 getDay()===0||6）|

### 交互规格
- **签到按钮点击**: Toast 确认弹窗 "确认签到？当前时间 09:15"，确认后 POST 请求，成功 Toast 绿色 "签到成功"
- **签退同理**
- **失败处理**: Toast 红色 "打卡失败，请检查网络"
- **乐观更新**: 按钮立即变灰，API 失败后回滚
- **位置信息**: 暂不做 GPS（演示环境无需），预留字段即可

### API 对应
```
GET  /staff-attendance/today          → 获取今日考勤状态
POST /staff-attendance/check-in       → 签到
POST /staff-attendance/check-out      → 签退
```

## 质量红线（每项功能完成后必须自查）

```
□ 加载状态: 数据请求中有 Skeleton 或 SpinLoading（不能白屏）
□ 空状态: 无数据时有图标 + 提示文字（不能空白）
□ 错误状态: 接口失败有 Toast 或内联提示（不能静默失败）
□ 下拉刷新: 列表页面支持 PullToRefresh（antd-mobile 组件）
□ 交互反馈: 点击按钮有 loading 状态，成功/失败有 Toast
□ i18n: 所有用户可见字符串均通过 t() 翻译
□ TypeScript: 无 @ts-ignore，无 any（用具体类型）
□ 视觉: 用 Playwright 截图确认，与 antd-mobile 设计语言一致
```
